# Writing with an Agent

You can write here the slow way — the pencil icon on GitHub, a sentence, a commit. You can also hand the binder to a GitHub-authed agent and speak in ordinary language: add a chapter about the river, fix the typo in chapter two, publish this when the dedication is done.

The agent is not a second product. It uses the same files a person would. It must not invent a config format, a build step, or a page of JavaScript to hold your prose. If the change cannot be explained as “edit this Markdown,” it does not belong in a book folder.

A good session looks like this. You name the book. The agent copies the template to a slug, fills the title and your GitHub name, leaves Status as Drafting, and adds the slug to the chapter-feedback dropdown. You talk the chapters into being, one file at a time. After a push you open the unlisted reader URL and look at the spread. When the book is ready, the agent sets Status to Published and adds one row to the portal README. That is the whole publishing motion.

Preserve the author's voice. An agent that “clarifies” every sentence will sand off the thing you meant. Ask for a change; get that change; leave the neighboring paragraphs alone.

If you are new to git, you still do not have to learn it. The author guide on GitHub walks through the website. The agent is another pair of hands on the same website, nothing more.
